# وضعیت آریا کالر — مرحله دوم، ۱۷ سپتامبر ۲۰۲۶

این نسخه یک مرحله اجرایی از پروژه است؛ تحویل کامل production-ready همه نیازمندی‌ها نیست.

## بخش عمومی
- طراحی RTL، هدر واکنش‌گرا، لوگوی آپلودشده، Hero ویدیویی با توقف دستی و reduced motion، پالت سرمه‌ای/طلایی/کرم.
- خانه، معرفی، فهرست خدمات و ۸ جزئیات خدمت، آرشیو تصاویر با جستجو/فیلتر و ۴ جزئیات، قبل/بعد قابل کنترل با صفحه‌کلید، بررسی هماهنگی پالت.
- فرم مشاوره، بازدید، پیشنهاد قیمت و API PostgreSQL واقعی؛ اعتبارسنجی سمت سرور، Origin check، سقف اندازه streaming، honeypot و محدودیت اتمیک دیتابیسی.
- بدون تنظیمات سرور فرم غیرفعال و API با 503 پاسخ می‌دهد؛ موفقیت جعلی ندارد.

## حساب کاربری و مدیریت درخواست‌ها
- ثبت‌نام و ورود واقعی؛ scrypt با salt تصادفی، رمز ۱۲ تا ۱۲۸ نویسه، نشست تصادفی ۲۵۶بیتی و نگهداری hash نشست در دیتابیس.
- کوکی HttpOnly / SameSite=Lax / Secure در production، انقضای ۷روزه، خروج با ابطال نشست دیتابیسی، کنترل Origin و محدودیت تلاش ورود.
- حساب عمومی همیشه USER است؛ ارسال role از کلاینت به ارتقای دسترسی منجر نمی‌شود.
- داشبورد مشتری با آمار واقعی، تاریخچه صفحه‌بندی‌شده، جستجو و فیلتر، جزئیات مالکیت‌محور، ویرایش پروفایل و اعلان‌های خصوصی.
- درخواست ثبت‌شده هنگام ورود به کاربر مرتبط می‌شود. درخواست مهمان صرفاً با ایمیل یا شماره به حسابی منتسب نمی‌شود.
- داشبورد مدیر با تعداد کاربران و درخواست‌های واقعی، فهرست جستجو/فیلتر/ترتیب/صفحه‌بندی و تغییر وضعیت درخواست.
- کنترل دسترسی در صفحات و API: USER و EDITOR به درخواست‌های خصوصی مدیریت دسترسی ندارند؛ ADMIN و SUPER_ADMIN مجازند. بخش CMS مختص Editor هنوز پیاده‌سازی نشده است.
- تغییر وضعیت با کنترل هم‌زمانی updatedAt؛ تغییر stale با 409 رد می‌شود. اعلان مشتری در همان تراکنش ساخته می‌شود.
- ابزار promote-admin فقط در محیط قابل اعتماد سرور و پس از تأیید هویت اجرا می‌شود؛ همه نشست‌های کاربر پس از تغییر نقش باطل می‌شوند. هیچ مسیر عمومی برای ارتقای نقش وجود ندارد.

## موارد باقی‌مانده
- بازیابی رمز و تأیید ایمیل، سرویس ارسال ایمیل، تغییر امن ایمیل/رمز، MFA مدیر، ثبت audit log کامل.
- CMS و CRUD محتوا، مدیریت کاربران از پنل، Media Library، S3 و آپلود امن، برآورد قیمت با تعرفه تأییدشده، بلاگ و جستجوی سراسری، نظرات/FAQ، صفحات حقوقی نهایی، Analytics.
- محتوای خدمات و پروژه‌ها هنوز فایل‌محور است؛ جایگزینی با دیتابیس/CMS ضروری است. نمونه تصاویر تا تأیید مالک برند پروژه واقعی محسوب نمی‌شوند.
- احراز مالکیت ایمیل هنوز پیاده‌سازی نشده؛ پیش از انتشار ثبت‌نام عمومی باید تکمیل شود. صفحه بازیابی صریحاً غیرفعال است و ادعای ارسال ایمیل ندارد.
- تست کامل WCAG، Lighthouse، همه مسیرهای درخواستی و مرورگرها، Docker deployment، نسخه موبایل بهینه ویدیو، CSP، CAPTCHA/edge rate limiting و پایش عملیاتی.
- اتصال به دیتابیس و دامنه واقعی، ذخیره امن رسانه، پشتیبان خودکار و آزمون restore هنوز لازم است.
- محدودیت فعلی ثبت درخواست: ۳ درخواست/شماره/ساعت، ۱۰۰ درخواست/کل سایت/ساعت. ورود: ۸ تلاش/ایمیل/۱۵ دقیقه و ۱۲۰ تلاش/کل سایت/۱۵ دقیقه. حفاظت edge برای جلوگیری از abuse توزیع‌شده لازم است؛ محدودیت‌ها امکان اختلال عمدی در دسترس‌پذیری را کاملاً رفع نمی‌کنند.
- پاک‌سازی زمان‌بندی‌شده نشست‌های منقضی و RateLimit، سیاست نگهداری داده و بررسی حقوقی باید قبل از انتشار اضافه شوند.
