# حساب‌ها و دسترسی‌ها

## راه‌اندازی
متغیرهای DATABASE_URL، RATE_LIMIT_SECRET و NEXT_PUBLIC_SITE_URL لازم‌اند. در production سایت باید HTTPS داشته باشد؛ کوکی نشست از نام __Host-aria-session استفاده می‌کند و Secure است. هیچ تنظیمی برای غیرفعال‌کردن امنیت کوکی در production اضافه نشده است.

کاربر با /register ثبت‌نام و از /login وارد می‌شود. نقش همیشه USER است. تاریخچه فقط درخواست‌های ثبت‌شده در زمان ورود همان کاربر را نشان می‌دهد؛ ایمیل یا شماره تماس معیار انتساب درخواست مهمان نیست.

## اولین مدیر
۱. حساب موردنظر را ثبت کنید.
۲. مالکیت حساب و هویت مدیر را خارج از سامانه تأیید کنید؛ تأیید ایمیل خودکار هنوز اضافه نشده است.
۳. در میزبان مطمئن، DATABASE_URL را بارگذاری و با Bun اجرا کنید:

```sh
bun scripts/promote-admin.ts verified-address@example.com SUPER_ADMIN
```

همه نشست‌های این حساب باطل می‌شوند. پس از ورود مجدد، حساب به /admin هدایت می‌شود. این ابزار وب endpoint ندارد. رمز مدیر پیش‌فرض یا hard-coded وجود ندارد.

| نقش | دسترسی فعلی |
|---|---|
| USER | حساب، درخواست و اعلان خودش |
| EDITOR | حساب خودش؛ بخش مدیریت محتوا هنوز پیاده‌سازی نشده |
| ADMIN | رسیدگی به تمام درخواست‌ها و آمار کسب‌وکار |
| SUPER_ADMIN | فعلاً دسترسی درخواست مشابه ADMIN؛ مدیریت نقش از پنل هنوز وجود ندارد |

ویرایش email و بازیابی password عمداً فعال نشده‌اند تا جریان تأیید و ارسال ایمیل امن ساخته شود. انتشار عمومی پیش از تکمیل این موارد و بررسی امنیت توصیه نمی‌شود.

## تست یکپارچه
فقط روی PostgreSQL محلیِ جدا با نام دیتابیس منتهی به `_test` اجرا کنید. اسکریپت برای تست محدودیت تلاش، رکوردهای RateLimit را پاک می‌کند؛ روی دیتابیس واقعی اجرا نکنید.

- برنامه را با DATABASE_URL همان دیتابیس تست، RATE_LIMIT_SECRET آزمایشی و NEXT_PUBLIC_SITE_URL=http://localhost:3090 اجرا کنید.
- TEST_DATABASE_URL و TEST_ORIGIN=http://localhost:3090 را تنظیم کنید.
- از ریشه پروژه اجرا کنید: `bun scripts/integration-test.ts`.

اسکریپت حساب و درخواست آزمایشی می‌سازد، ایمیل خارجی ارسال نمی‌کند و رمز یا cookie را در گزارش نمی‌نویسد. گزارش پیش‌فرض در `/tmp/aria-integration-report.json` است.
